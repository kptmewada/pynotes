Question 1

What is Python? Four features that make it popular

Python is a high-level, general-purpose, interpreted programming language created by Guido van Rossum in 1991. It emphasizes code readability and simplicity, enabling developers to write fewer lines of code compared to languages like C++ or Java. Python supports multiple programming paradigms: procedural, object-oriented, and functional.

📖 Simple & Readable Syntax

Python's syntax is close to plain English. There are no unnecessary curly braces or semicolons, making it very easy to read and write, especially for beginners.

🌐 Versatile & Multi-purpose

Used in web development (Django, Flask), data science (NumPy, Pandas), AI/ML (TensorFlow), automation, scientific computing, and more.

📦 Rich Standard Library

Python ships with a large built-in library ("batteries included") plus thousands of third-party packages on PyPI, reducing the need to write code from scratch.

🔁 Interpreted & Interactive

Code runs line-by-line without a separate compilation step. This makes testing and debugging faster, and the REPL allows instant feedback while learning.

Question 3

Dynamically Typed Language — with Python example

In a dynamically typed language, the type of a variable is determined at runtime, not at compile time. You do NOT need to declare the type of a variable when writing code. The same variable can hold values of different data types at different points in the program.

This contrasts with statically typed languages (like C, Java) where you must declare the type explicitly (e.g., int x = 5;) and it cannot change.

# Python is dynamically typed — no type declaration needed
x = 10
print(type(x))      # <class 'int'>

x = "Hello"
print(type(x))      # <class 'str'>

x = 3.14
print(type(x))      # <class 'float'>

x = [1, 2, 3]
print(type(x))      # <class 'list'>

# The same variable 'x' held int, str, float, and list — perfectly valid!
⚠️ While dynamic typing is convenient, it can lead to runtime errors if the type changes unexpectedly. Python 3.5+ supports type hints (e.g., x: int = 5) for readability, but these are not enforced at runtime.

Question 5

Type Casting (Type Conversion) — Implicit & Explicit

Type casting (also called type conversion) is the process of converting a value from one data type to another.

1. Implicit Type Casting (Coercion) — Done automatically by Python without any user involvement. Python promotes the smaller/less precise type to the larger/more precise type to avoid data loss.

# Implicit: Python converts int → float automatically
a = 5       # int
b = 2.5     # float
result = a + b
print(result)          # 7.5
print(type(result))    # <class 'float'>

# Another example: bool is treated as int
print(True + 10)       # 11  (True = 1)

2. Explicit Type Casting — Done manually by the programmer using built-in functions like int(), float(), str(), list(), etc.

# int() — converts to integer
print(int(3.9))       # 3  (truncates, does NOT round)
print(int("25"))     # 25

# float() — converts to float
print(float(7))      # 7.0
print(float("3.14")) # 3.14

# str() — converts to string
print(str(100))      # "100"
print(str(3.14))     # "3.14"

# list() and tuple() conversions
print(list((1, 2, 3)))  # [1, 2, 3]
print(tuple([4, 5]))    # (4, 5)
⚠️ Not all conversions are valid. int("Hello") raises a ValueError. Always ensure the value is compatible with the target type.

Keywords in Python — Why can't they be used as variable names?

Keywords are reserved words in Python that have special, predefined meanings in the language's syntax and grammar. They form the building blocks of Python programs — they define structure, control flow, logical operations, etc.

Python has 35 keywords (as of Python 3.10+):

Why can't keywords be used as variable names?

if, if-else, and elif statements

1. if statement — Executes a block only if the condition is True.

Syntax
if condition:
    # block executed if condition is True
Real-life example — checking if a student passes
marks = 55
if marks >= 35:
    print("You have passed the exam.")
# Output: You have passed the exam.

2. if-else statement — Executes one block if condition is True, another block if False.

Syntax
if condition:
    # block if True
else:
    # block if False
Real-life example — ATM withdrawal
balance = 5000
amount = 3000
if amount <= balance:
    print("Withdrawal successful.")
else:
    print("Insufficient balance.")
# Output: Withdrawal successful.

3. elif statement — Checks multiple conditions in sequence. Stands for "else if".

Syntax
if condition1:
    # block if condition1 is True
elif condition2:
    # block if condition2 is True
elif condition3:
    # block if condition3 is True
else:
    # block if all conditions are False
Real-life example — grading system
marks = 78
if marks >= 90:
    grade = "A+"
elif marks >= 80:
    grade = "A"
elif marks >= 70:
    grade = "B"
elif marks >= 60:
    grade = "C"
else:
    grade = "Fail"
print(f"Grade: {grade}")  # Grade: B
💡 Python evaluates conditions from top to bottom and executes only the first matching block. Once a condition is True, the rest are skipped.

Question 10

else clause with loops — when is it executed?

Python uniquely allows an else block to be attached to both for and while loops. The else block executes when the loop completes normally — i.e., it is NOT executed if the loop was terminated by a break statement.

Rule: else runs → loop finished without break. else is skipped → loop was broken with break.
# else with for loop — searching for a number
numbers = [10, 20, 30, 40]
target = 25
for n in numbers:
    if n == target:
        print("Found!")
        break
else:
    print("Number not found in list.")
# Output: Number not found in list.  (because 25 is not in list)

# else with while loop
count = 0
while count < 3:
    print(f"count = {count}")
    count += 1
else:
    print("Loop ended normally.")
# count = 0
# count = 1
# count = 2
# Loop ended normally.
✅ Use case: The loop-else pattern is very useful for search algorithms — run the loop to search; if not found (no break), the else block handles the "not found" case elegantly.

Question 12

The pass statement — role inside a loop

pass is a null statement in Python. It does absolutely nothing when executed. It is used as a placeholder where syntactically a block of code is required, but you don't want to write any code yet (or intentionally want to do nothing).

Why is pass needed? Python uses indentation to define blocks. If you write for i in range(5): and leave the body empty, Python gives a SyntaxError. The pass statement satisfies the syntax requirement while doing nothing.

# Without pass — SyntaxError!
# for i in range(5):
#     ← empty body causes SyntaxError

# With pass — valid, does nothing
for i in range(5):
    pass   # placeholder: logic to be added later

# Common use: placeholder while developing
def calculate_tax(income):
    pass    # TODO: implement later

# Useful in exception handling
try:
    x = int("abc")
except ValueError:
    pass    # silently ignore the error

# Difference from break/continue:
# break  → exits the loop
# continue → skips current iteration
# pass   → does nothing, loop continues normally
for i in range(5):
    if i == 3:
        pass      # nothing special happens at i=3
    print(i, end=" ")
# Output: 0 1 2 3 4  (all values, pass changed nothing)
✅ Summary: pass is mainly used during development as a placeholder, to silence syntax errors in empty blocks, or when you intentionally want a loop/function/class body that does nothing.

What is a function in Python? Explain with a suitable example.

A function is a named, reusable block of code designed to perform a specific task. Instead of writing the same logic repeatedly, you define it once and call it wherever needed. Functions improve code reusability, readability, and modularity.

Python has two types of functions:

  • Built-in functions — provided by Python itself (e.g., print(), len(), range())
  • User-defined functions — created by the programmer using the def keyword
Syntax
def function_name(parameters):
    """Optional docstring — describes the function"""
    # body of the function
    return value   # optional
Example — calculate area of a rectangle
def calculate_area(length, width):
    """Returns the area of a rectangle."""
    area = length * width
    return area

# Calling the function
result = calculate_area(10, 5)
print(f"Area = {result}")   # Area = 50

# Can be called multiple times with different inputs
print(calculate_area(7, 3))  # 21
💡 A function is defined once with def and can be called any number of times. The return statement sends a value back to the caller.

Why is indentation mandatory in Python? What error occurs on wrong indentation?

In most languages (C, Java, JavaScript), code blocks are defined using curly braces {}, and indentation is optional (only for readability). In Python, indentation IS the syntax — it is the only way Python identifies what belongs inside a function, loop, or conditional block.

Python's design philosophy (PEP 8) enforces indentation to make code uniformly readable and to eliminate ambiguity about block boundaries.

Question 17

Variable Scope in Python — The LEGB Rule

Scope refers to the region of a program where a variable is accessible. Python follows the LEGB rule to resolve variable names — it searches scopes in this order:

L — Local

Variables defined inside the current function. Accessible only within that function.

E — Enclosing

Variables in the scope of any enclosing (outer) function — applies to nested functions.

G — Global

Variables defined at the top level of the module/script, outside all functions.

B — Built-in

Names pre-defined in Python's built-in namespace: print, len, range, int, etc.

# LEGB Rule illustrated
x = "global"            # G — Global

def outer():
    x = "enclosing"      # E — Enclosing

    def inner():
        x = "local"      # L — Local
        print(x)         # local   (L found first)
        print(len)       # B — Built-in (len is a built-in)

    inner()
    print(x)             # enclosing

outer()
print(x)                 # global
💡 Python searches L → E → G → B and uses the first match it finds. If the name is not found in any scope, a NameError is raised.

Question 19

The global keyword — and why overusing it is bad practice

By default, a variable assigned inside a function is local. The global keyword tells Python that a variable inside a function refers to the global (module-level) variable, allowing you to read and modify it from within the function.

counter = 0              # global variable

def increment():
    global counter        # declare we want the global one
    counter += 1

increment()
increment()
print(counter)           # 2

# Without global keyword:
def bad_increment():
    counter += 1          # UnboundLocalError! Python treats it as local

Why overusing global variables is bad practice:

  • Hard to debug — any function anywhere can change a global variable, making it difficult to trace the source of a bug.
  • Breaks encapsulation — functions should work with their inputs (parameters) and return outputs, not silently rely on external state.
  • Not thread-safe — in multi-threaded programs, multiple threads modifying a global variable leads to race conditions.
  • Reduces reusability — a function that depends on globals can't be easily reused in another program.
✅ Better alternative: Pass values as function arguments and return results. This makes functions pure and predictable.
Question 20

The nonlocal keyword — nested functions

The nonlocal keyword is used inside a nested (inner) function to refer to and modify a variable defined in the immediately enclosing (outer) function's scope — without affecting the global scope.

It is the nested-function equivalent of global — but instead of reaching all the way to the global scope, it reaches only to the nearest enclosing scope.

def outer():
    count = 0               # enclosing variable

    def inner():
        nonlocal count      # refer to outer's count
        count += 1
        print(f"inner: count = {count}")

    inner()
    inner()
    print(f"outer: count = {count}")

outer()
# inner: count = 1
# inner: count = 2
# outer: count = 2

# Practical use: closure-based counter (no global needed)
def make_counter():
    n = 0
    def counter():
        nonlocal n
        n += 1
        return n
    return counter

c = make_counter()
print(c(), c(), c())   # 1 2 3
💡 nonlocal is mainly used in closures — inner functions that remember and modify state from their enclosing function.
Question 21

Recursion vs Iteration — advantages and disadvantages

Recursion is a programming technique where a function calls itself to solve a problem by breaking it into smaller sub-problems of the same type. Iteration uses loops (for/while) to repeat a block of code.

AspectRecursionIteration
ApproachFunction calls itself with a simpler inputUses a loop to repeat code
TerminationBase case stops the recursionLoop condition becomes False
Memory useHigher — each call adds a stack frameLower — single stack frame
SpeedSlower due to function call overheadFaster in most cases
Code clarityElegant for tree/graph problems, factorial, FibonacciClearer for simple repetition
RiskStack overflow if base case is missingInfinite loop if condition never False
Best forDivide-and-conquer, tree traversal, backtrackingSimple counters, array processing
# Factorial — recursive approach
def factorial_recursive(n):
    if n == 0:
        return 1            # base case
    return n * factorial_recursive(n - 1)   # recursive case

# Factorial — iterative approach
def factorial_iterative(n):
    result = 1
    for i in range(1, n + 1):
        result *= i
    return result

print(factorial_recursive(5))   # 120
print(factorial_iterative(5))    # 120
Question 22

Two essential parts of a recursive function — Base case & Recursive case

Every correct recursive function must have exactly two parts:

  • Base case — The simplest version of the problem that can be solved directly without further recursion. It stops the recursion. Without it, the function recurses infinitely and causes a RecursionError (stack overflow).
  • Recursive case — The part where the function calls itself with a simpler or smaller input, moving the problem toward the base case.
# Example 1: Factorial
def factorial(n):
    if n == 0 or n == 1:       # BASE CASE: factorial(0)=1, factorial(1)=1
        return 1
    return n * factorial(n - 1)  # RECURSIVE CASE: problem gets smaller

# Call trace for factorial(4):
# factorial(4) = 4 * factorial(3)
#              = 4 * 3 * factorial(2)
#              = 4 * 3 * 2 * factorial(1)
#              = 4 * 3 * 2 * 1  ← base case hit
#              = 24

# Example 2: Fibonacci
def fib(n):
    if n <= 1:                   # BASE CASE
        return n
    return fib(n-1) + fib(n-2)   # RECURSIVE CASE

print(fib(7))    # 13   (sequence: 0,1,1,2,3,5,8,13...)
⚠️ Python's default recursion limit is 1000 calls. For deeper recursion, use sys.setrecursionlimit() — or better, switch to an iterative approach.

The built-in input() function reads whatever the user types from the keyboard as raw text. Why are strings immutable in Python? — with example

A string is immutable because once created, its content cannot be changed. You cannot modify, insert, or delete individual characters. Any operation that appears to "modify" a string actually creates a new string object.

Why are strings made immutable?

  • Hashability — Immutable strings can be used as dictionary keys and set elements. If strings could change, their hash would change, breaking dictionaries.

Question 38

Why are lists called mutable sequences? — aliasing and shared references

Lists are called mutable sequences because they are ordered (sequence) and their contents can be changed in-place (mutable) — elements can be added, removed, or modified without creating a new object.

A key consequence of mutability is aliasing: when you assign one list variable to another, both variables point to the same object in memory. Modifying the list through one reference affects all references.

# Demonstrating aliasing — shared reference
a = [1, 2, 3]
b = a               # b is NOT a copy — b points to the same list

print(id(a) == id(b))   # True — same object in memory

b[0] = 999          # modify through b
print(a)            # [999, 2, 3]  ← a is affected too!
print(b)            # [999, 2, 3]

b.append(4)
print(a)            # [999, 2, 3, 4]  ← still both refer to same list

# ✅ To avoid aliasing — make a copy
a = [1, 2, 3]
b = a.copy()        # shallow copy — b is a new list
b[0] = 999
print(a)            # [1, 2, 3]   ← a is unaffected
print(b)            # [999, 2, 3]

# Other ways to copy a list
c = a[:]            # slice copy
d = list(a)         # constructor copy
⚠️ b = a does NOT copy the list — it creates a second alias (reference) to the same list. Always use .copy(), slicing [:], or list() when you need an independent copy.

Question 40

What is a dictionary? Internal implementation (hash table) and why keys must be immutable

A dictionary (dict) is an unordered* collection of key-value pairs. It provides very fast lookup, insertion, and deletion — all in average O(1) time. Dictionaries are the most widely-used mapping type in Python.

*As of Python 3.7+, dictionaries maintain insertion order as an implementation detail (and officially guaranteed from 3.7).

Internal Implementation — Hash Table:

Python dictionaries are implemented as hash tables. Here is how they work:

  1. When you insert a key-value pair, Python calls hash(key) to compute an integer hash value.
  2. The hash value determines the bucket (slot) where the value is stored in an internal array.
  3. On lookup (d[key]), Python computes hash(key) again and jumps directly to that slot — no scanning needed, hence O(1).
  4. When two keys produce the same hash (collision), Python resolves it using open addressing (probing adjacent slots).

Why keys must be immutable (hashable):

The hash value of a key must remain constant for the lifetime of the key in the dictionary. If a key could change, its hash would change, and Python would look in the wrong slot — losing the value entirely. Immutable types (int, str, tuple of immutables) have stable hashes. Mutable types (list, dict, set) do not support hashing at all.

# Creating a dictionary
student = {"name": "Alice", "age": 21, "gpa": 9.1}

# ✅ Valid key types (immutable/hashable)

# ❌ Invalid key types (mutable/unhashable)
# d = {[1, 2]: "list key"}   → TypeError: unhashable type: 'list'
# d = {{1: 2}: "dict key"}   → TypeError: unhashable type: 'dict'

# hash() values for immutable types

print(hash(42))         # 42

The else clause in exception handling — purpose and when it executes

The else clause in a try-except block executes only when the try block completes without raising any exception. It is the "success path" — code that should only run if everything in try went smoothly.

Why have else at all? You could put the success code inside the try block itself — but that would incorrectly catch exceptions from that success code too. The else clause lets you separate "risky code" (in try) from "code that runs on success but shouldn't be guarded" (in else).

    print("Not a valid number")

# ✅ With else — precise and clean

    num = int(input("Enter a number: "))    # ONLY this might raise ValueError

    print("Not a valid number")

Why is __init__() used in Python?

__init__() is a special method (called a dunder / magic method) that Python calls automatically whenever a new object is created from a class. Its job is to initialise the object's attributes — setting the starting state of the new instance.

It is equivalent to a constructor in languages like Java or C++. The name stands for initialise. Python first creates the object in memory (via __new__) and then immediately calls __init__ on it.

Syntax

        self.attr2 = param2

    def __init__(self, name, grade):
        self.name  = name       # initialised instantly
        self.grade = grade
        self.passed = grade != "F"   # derived attribute

    def info(self):
        status = "Pass" if self.passed else "Fail"
        print(f"{self.name} | Grade: {self.grade} | {status}")

Question 59

What is Polymorphism? Explain method overriding and duck typing in Python.

Polymorphism (Greek: many forms) means the ability to use a single interface to represent different types. The same method name or operator behaves differently depending on the object it acts on. Python achieves polymorphism mainly through method overriding and duck typing.

Method Overriding

A child class redefines a method that already exists in the parent class. When the method is called on a child object, Python uses the child's version, not the parent's.

Duck Typing

"If it walks like a duck and quacks like a duck, it's a duck." Python doesn't care about the type of the object — only whether it has the required method or attribute.

Method Overriding example
class Shape:
    def area(self):
        return 0                       # default — overridden by each child

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    def area(self):                    # OVERRIDE
        return 3.14 * self.radius ** 2

class Rectangle(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h
    def area(self):                    # OVERRIDE
        return self.w * self.h

shapes = [Circle(5), Rectangle(4, 6), Shape()]
for s in shapes:
    print(s.area())       # same call → different result
# 78.5
# 24
# 0
Duck Typing example
class Dog:
    def speak(self): return "Woof!"

class Cat:
    def speak(self): return "Meow!"

class Robot:
    def speak(self): return "Beep boop!"

# No shared parent class — Python only checks: does it have speak()?
def make_it_speak(thing):
    print(thing.speak())      # duck typing — works for any object with speak()

for obj in [Dog(), Cat(), Robot()]:
    make_it_speak(obj)
# Woof!
# Meow!
# Beep boop!
💡 Python does not support method overloading (same method name, different parameter types) the way Java/C++ do. Instead, Python uses default arguments and *args/**kwargs to achieve the same effect in a single method definition.
Question 60

What is Encapsulation? How is Information Hiding achieved in Python?

Encapsulation is the OOP principle of bundling data (attributes) and the methods that operate on that data together inside a class, while restricting direct access to some of the object's internal details. This protects the internal state from unintended modification and exposes only a controlled interface to the outside world.

Python does not enforce access control at the language level (unlike Java's private keyword). Instead it uses a naming convention to signal the intended visibility:

class BankAccount:
    def __init__(self, owner, balance):
        self.owner    = owner          # public
        self._bank    = "SBI"         # protected — internal use
        self.__balance = balance       # private — name mangled to _BankAccount__balance

    # Getter — controlled read access
    def get_balance(self):
        return self.__balance

    # Setter — controlled write access with validation
    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit must be positive")
        self.__balance += amount

    def withdraw(self, amount):
        if amount > self.__balance:
            raise ValueError("Insufficient funds")
        self.__balance -= amount

acc = BankAccount("Aisha", 5000)
print(acc.owner)             # Aisha  ← public, fine
print(acc.get_balance())     # 5000   ← via getter, fine
acc.deposit(1000)
print(acc.get_balance())     # 6000

print(acc.__balance)         # AttributeError — cannot access directly
print(acc._BankAccount__balance)  # 6000 ← mangled name (avoid in real code)

Question 61

Explain Name Mangling in Python — syntax, purpose, and why it is used.

Name mangling is Python's mechanism for making an attribute harder to accidentally access or override from outside the class or from subclasses. When you prefix an attribute or method name with two leading underscores (and at most one trailing underscore), Python automatically renames it at compile time by prepending _ClassName.

The transformation rule
# What you write inside the class:
self.__secret

# What Python actually stores it as:
self._ClassName__secret
Example demonstrating name mangling
class Counter:
    def __init__(self):
        self.__count = 0          # stored as _Counter__count

    def increment(self):
        self.__count += 1

    def get_count(self):
        return self.__count

c = Counter()
c.increment()
c.increment()
print(c.get_count())      # 2  ← correct way

print(c.__count)          # AttributeError: 'Counter' object has no attribute '__count'
print(c._Counter__count)  # 2  ← mangled name still accessible (for debugging)

# Name mangling prevents accidental override in subclasses
class SubCounter(Counter):
    def __init__(self):
        super().__init__()
        self.__count = 99   # stored as _SubCounter__count — DIFFERENT attribute!

sc = SubCounter()
sc.increment()           # modifies _Counter__count, not _SubCounter__count
print(sc.get_count())    # 1  ← Counter's __count, unaffected by SubCounter's __count
print(sc._SubCounter__count)  # 99
